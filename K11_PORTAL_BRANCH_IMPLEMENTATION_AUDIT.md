# Independent implementation audit of the `k=11` portal branches

## Verdict

**PASS** for both implemented modes:

```text
K11_FOREST_PORTAL_BRANCH=q19_factor_prefix
K11_FOREST_PORTAL_BRANCH=q19_fixed_row
```

The implementation adds exact unit-clause restrictions to the already
audited `k=11,n=465` forest kernel.  I found no wrong state, physical index,
mask-column index, entry-bit sign, endpoint-threshold sign, variable-count
change, or clause-count discrepancy.  With the switch absent, the SAT
variable allocation and hard-clause stream are unchanged.

The theorem scope remains deliberately narrow.  SAT in either branch, after
decoding and independent interval-OR verification, proves `nu(11)=465`.
UNSAT refutes only that named prefix branch and says nothing about another
length-465 monotone-band schedule or the unrestricted conjecture.

I also independently checked the local `q=19` certificate and the preceding
metric-optimal `q=18` nonexistence claim.  The supplied certificate passes.
Within the stated Johnson-geodesic model, no factorable `q=18` lift exists.
Two possible gaps in that exhaustive claim--an unnamed terminal bridge and a
repeated intermediate portal colour--were checked separately and do not
change the result.

## 1. Mode parsing and prerequisite gate

The parser accepts exactly `q19_factor_prefix` and `q19_fixed_row`.  An
unknown nonempty value exits with status 2.  A selected portal mode requires
both

```text
K11_FOREST_ADJACENT_SHADOWS=1
K11_FOREST_RANK3_SHADOWS=1.
```

It rejects every pre-existing optional structural module: band, joint-band,
endpoint-alignment, coordinate-canonical rank-six entry, singleton pool,
rank-six boundary entry, local-density PB, either rank-six branch, and either
minimal-component portfolio.  Exact containment caps are intentionally the
sole optional strengthening allowed with a portal mode.

I exercised four negative cases remotely.  An invalid name, a portal mode
without the two shadow modules, rank-three shadows without adjacent shadows,
and a portal mode with band cuts all exited with status 2 and the intended
diagnostic before formula construction.

The guard is stricter than branch soundness strictly needs, but that is safe:
it prevents accidentally combining the fixed decimal prefix with coordinate
symmetry breaks that are not invariant under it.

## 2. Exact central-state schedule

The inherited state order is

```text
00 01 02 03 11 12 13 22 23 33.
```

At ordered central index `i`, state `(alpha,beta)` denotes the physical
zero-based interval `[i+alpha,i+beta]`.  The source obtains states `02` and
`03` by `state_index`, rather than relying on magic numeric indices, and adds

```text
state6[i]=02,  0 <= i <= 18;
state6[i]=03, 19 <= i <= 461.
```

Thus the first nineteen selected rank-six witnesses are precisely the
one-based triple windows `R3(1),...,R3(19)`, and the remaining 443 are the
one-based quadruple windows `R4(20),...,R4(462)`.  All endpoints lie in the
465-entry word.  This is exactly schedule (6.1)--(6.2) of the design.

The inherited formula already gives each row exactly one monotone state,
links its eleven value bits bidirectionally to that physical interval OR,
enforces weight six, and makes the 462 values a permutation of the rank-six
layer.  The new state units therefore impose actual windows, not detached
metadata.

## 3. Fixed-row mask indexing

`CentralLayer::q` is allocated and used row-major as

```text
q[i * 462 + column].
```

The rank-six mask vector is generated by scanning decimal masks in increasing
order.  The implementation uses `lower_bound` and verifies equality before
forming every unit.  The independently recomputed zero-based mask columns
are:

```text
row:mask(column)
 0:489(77)    1:429(56)    2:940(190)   3:828(154)
 4:860(164)   5:1876(434)  6:1862(428)  7:1734(393)
 8:1731(391)  9:1251(256) 10:243(22)   11:123(4)
12:95(1)     13:543(84)   14:670(109)  15:1690(379)
16:1434(309) 17:1436(310) 18:444(63).
```

A positive `q` literal is exact here.  It implies all six positive mask bits;
the row has exact cardinality six, so its value equals the mask.  Coverage of
all 462 mask columns by 462 rows then makes the layer a permutation.  No
missing negative-bit implication weakens the fixed-row units.

## 4. Fixed entry bits and the `958` endpoint units

In `q19_factor_prefix`, the 22 decimal entries are expanded into all
`22*11=242` signed units.  C++ operator precedence parses

```text
entry & (1 << bit) ? A(position,bit) : -A(position,bit)
```

as intended.  Hence every one-bit position is positive and every zero-bit
position is negative; this is exact equality, not containment.

In `q19_fixed_row`, rank eight remains in `direct`, so target `958` has the
ordinary exact unary endpoint encoding.  Its conventions are

```text
L(p) <=> p >= selected left endpoint,
R(p) <=> p <= selected right endpoint.
```

The four source units are

```text
 L(18), -L(17), R(21), -R(22).
```

They fix the zero-based interval `[18,21]`, which is the one-based seam
`R4(19)`.  The signs are correct.  The inherited inside and exact-bit clauses
then force this witness OR to equal `958`.

The factor-prefix mode does not add these four endpoint units.  That is not a
gap: its fixed entries already make physical window `[18,21]` equal `958`,
and this length-four interval is legal for the direct rank-eight witness.  If
the rest of an entry assignment extends, its direct-target auxiliary
variables can select this known witness.

## 5. Why the fixed local data imply all advertised portals

Independent recomputation of the 22 entries gives:

```text
19 distinct triple ORs, all rank 6, equal to the displayed P row;
18 distinct quadruple ORs, all rank 7, equal to the displayed U row;
all 12 named missing rank-seven masks occur in U;
the nineteenth quadruple OR is 958 of rank 8;
the final three-entry OR is 550 of rank 4;
all 22 entries are nonzero.
```

For the fixed-row mode this also follows symbolically.  Two consecutive
triple windows have union equal to their containing quadruple window, so
fixing consecutive row values `P_i,P_(i+1)` forces portal
`P_i OR P_(i+1)=U_i`.  The explicit endpoint units force the final seam.

The standalone verifier was compiled with `-O3 -std=c++20 -Wall -Wextra
-Wpedantic` locally and with the pod compiler remotely.  Both executions
reported:

```text
PASS q=19 rank6_triples=19 rank7_portals=18 required_rank7=12
     seam=958 continuation_core=550/rank4
```

The verifier checks the certificate from the entries themselves; it does not
trust the listed `P` and `U` rows.

## 7. Disabled-mode clause-stream preservation

The recorded implementation patch is insertion-only.  It adds:

1. environment parsing and validation, which allocate no SAT variable;
2. one diagnostic counter initialized to zero;
3. all new calls to `add` inside `if (!portal_branch_mode.empty())`;
4. diagnostic output after all clauses have already been emitted.

No pre-existing allocation, clause, loop, phase, or ordering was changed.
Therefore, with the environment switch absent, `next` follows the identical
path and every pre-existing `solver.add` call receives the same literal in the
same order.  The remote absent-mode build also reproduces the audited kernel
inventory `2,882,282 / 14,352,124` (or `14,459,492` with caps).  The only
observable difference is the appended diagnostic text
`portal_branch=none portal_branch_clauses=0`; it is not part of the formula.

## 8. Audit of the `q=18` metric claim

The search first solves the Held--Karp path problem on the twelve required
rank-seven colours with Johnson distance

```text
d(X,Y)=7-|X intersection Y|.
```

It backtracks every target order attaining the optimum, enumerates every
Johnson geodesic between consecutive required colours, derives the forced
internal rank-six intersections, tries every legal rank-six facet at each
end, requires all rank-six central masks distinct, and checks the exact
delay-two factorability criterion: every internal coordinate 1-run has length
at least three.  These steps are exhaustive for the resulting geodesic walk
space.  A globally length-optimal walk can be decomposed this way: shortcutting
successive first visits cannot have total metric length below the Held--Karp
optimum, so every segment of an optimum walk is geodesic.

The remote rerun reports optimum 16 Johnson edges, exhausts that level without
a factorable lift, then finds the published prefix at limit 17:

```text
trying_metric_limit=17
optimum_edges=16 tested_orders=51 segment_combinations=134737
```

Two subtleties required extra checks.

First, the published code asks that the last *required* colour itself share a
rank-six facet with `958`.  An unrestricted optimum could in principle visit
its last required colour and then use an unnamed terminal bridge.  An
independent Held--Karp terminal calculation used terminal penalty

```text
max(0, 6-|last_required intersection 958|).
```

It gives optimum 16 both with an arbitrary seam-compatible final colour and
with the code's restricted required endpoint.  Moreover every endpoint that
attains the arbitrary optimum (`1468`, `1694`, or `1946`) is already
seam-compatible, so no omitted terminal-tail case exists at length 16.

Second, the published search rejects a rank-seven portal colour if it appeared
earlier.  Distinct portals are desirable for the `q=19` certificate but are
not logically required merely to cover the twelve targets.  I reran a
transient audit variant that retained distinct rank-six intersections while
allowing repeated nonconsecutive rank-seven portal colours.  It still
exhausted optimum 16 without a factorable lift and first found the same
certificate at limit 17 (`136465` segment combinations before termination).
Thus the extra rainbow restriction does not account for the `q=18` failure.

The result being certified is local and branch-specific:

> No delay-two-factorable rank-six lift of a Johnson-geodesic portal walk of
> 16 edges visits all twelve named rank-seven targets and can enter the `958`
> seam with distinct rank-six central values.

It is not an impossibility theorem for every conceivable length-465 OR word,
nor even for every different placement of those upper targets.

## 9. Final scope statement

Both implemented branches keep the full exact all-target kernel.  The rank
seven values found in the prefix are not treated as a substitute for the
remaining 318 rank-seven targets, and no witness from an old partial factor is
assumed to survive.  A SAT model therefore already assigns one common
465-entry word and exact witnesses for every nonzero 11-bit mask.  It must
still be decoded and accepted by both independent full-array verifiers before
being promoted.

Conversely, neither branch is WLOG:

* `q19_factor_prefix` fixes 242 entry bits of one particular local factor;
* `q19_fixed_row` fixes one particular sequence of nineteen rank-six masks and
  one seam witness;
* both fix the switch after nineteen shortened witnesses.

Proof-producing UNSAT is useful search information, but it proves only the
correspondingly named branch UNSAT.
