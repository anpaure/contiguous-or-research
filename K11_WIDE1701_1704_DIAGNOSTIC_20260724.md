## Concrete wide-LNS v3 recommendation

The current make_wide_candidates pipeline first sorts each class by the scalar
sum of unique-witness loads, truncates roughly 4,000 raw candidates to 64, and
only then computes the exact untouched repair-family size. It also constructs
optional positions from only three tie-shuffled global load orders and does
not deduplicate equivalent position/creator signatures before the
four-candidate exact quota. The logs' low novelty rates are consistent with
this funnel.

The v3 patch should replace that funnel with the already-audited simultaneous
addition ledger from k11_select_target_edit_sets.cpp:

1. For every mandatory creator set, beam-fill the remaining radius-6/7
   positions using the exact number of targets whose last untouched witness is
   destroyed by each addition.
2. Keep separate radius/style quotas, but deduplicate by
   (positions, creators, protected interval) before assignment search.
3. Rank first by exact repair-family size, then unique-witness load; retain a
   diversity quota for distinct repair families and position signatures.
4. Cache rejected signatures per current word. If a round returns a previously
   seen word/signature, advance to the next beam candidate instead of
   immediately recycling the same global best.

This is a local patch: it reuses exact witness data already computed by the
search and does not change the protected-target invariant or evaluator. A
second-stage improvement, after that patch is measured, is to seed assignment
values from the fixed-edit witness terms rather than drawing uniformly from
the endangered-mask pool.

No length-476 universal word or new lower bound is claimed here.
